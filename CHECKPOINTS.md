# Criterios de cierre

## Antes de implementar

- Spec, plan y tasks consistentes; dudas que afecten la tarea resueltas.
- Entrega de Codex `ready`, con tareas pendientes y comandos verificables.
- Stack y contratos definidos para el alcance; revisión de privacidad y seguridad cuando corresponda.

## Antes de cerrar una funcionalidad

- Criterios de aceptación demostrados con evidencia, incluidos errores relevantes.
- Pruebas de producto correspondientes ejecutadas; el verificador del arnés no prueba la aplicación.
- Informe de Claude y revisión independiente de Codex disponibles.
- Sin hallazgos críticos abiertos; tareas, estado y documentación actualizados.
- Memoria local actualizada y sincronización a NotebookLM registrada como realizada o pendiente.
- `init.ps1` correcto y `git diff --check` sin errores.

## Montaje inicial

Se entrega sin código de producto. Puede cerrarse el montaje aunque la autenticación de Google o la instalación de Claude Code sigan pendientes, siempre que se documenten y no se declare una conexión que no se probó.
